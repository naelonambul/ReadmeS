# 제품 범위와 개인 기여

[프로젝트 소개로 돌아가기](../README.md)

## 프로젝트 맥락

FC Smart Platform은 가맹본부와 매장의 관리 업무를 PC와 모바일에서 다루기 위한 프로젝트입니다. 매출·비용만 관리하는 단일 장부가 아니라, 회원·소속 관계, 현장 점검, 점주 상담, 소통, 일정과 운영 기능이 함께 있습니다.

프로젝트 기간은 **2019.12-2020.10**이며, 팀은 디자이너 1명과 본인을 포함한 개발자 2명으로 구성되었습니다. 기간·팀 구성·개인 기여 및 KPC의 계산 기준 제공은 본인의 참여 경험을 근거로 합니다.

## 본인이 담당한 범위

| 영역 | 본인의 기여 |
| --- | --- |
| 개발 전반 | 프로젝트 전반의 개발을 주도하고 주요 기술 스택 선택 |
| 기술 접근 | 웹·모바일·서버에 JavaScript 중심 개발 방식 선택 |
| 데이터베이스 | 전체 데이터베이스·스키마 설계 |
| API·백엔드 | API 설계, Node.js/Express 백엔드 대부분 개발 |
| React 웹 | 초기 애플리케이션 구조, 페이지 구성·라우팅 및 주요 개발 |
| 고객 요구 | 요구와 변경 사항을 데이터 구조, 기능, 업무 로직으로 구체화 |
| 인증·권한 | 설계와 구현에 참여 |
| React Native | 모바일 개발 협업. 기능 구현의 더 큰 비중은 다른 개발자가 담당 |

“개발을 주도했다”는 표현은 실제 맡은 범위에 대한 설명이며, 공식 직책을 뜻하지 않습니다. 전체 제품을 혼자 만들었다거나 모바일 기능 대부분을 구현했다고 주장하지 않습니다. Git 이력이 포함되지 않은 소스 보관본만으로 개별 기능의 작성자를 판정할 수도 없습니다.

| 운영·부가 기능 | 팝업, 운영자·회원 관리, 회원·접속 통계, CSV | 알림 수신, 지도 표시 | 외부 연동의 현재 운영 성공은 미검증 |

## 대표 흐름 1 — 현장 점검에서 보고서까지

본부별 점검 항목을 정의하고, 매장에서 수행한 점검의 점수·체크 결과를 회차별로 기록합니다. 모바일에는 사진과 서명을 연결하는 흐름이 있고, 백엔드는 항목별 결과와 리포트를 저장·조회합니다. 웹에서는 결과를 확인하고 점검 보고서를 Excel 파일로 구성합니다.

이 흐름은 현장 입력, 데이터 구조, API, 관리자 검토와 산출물이 하나의 업무로 연결되었다는 제품 증거입니다. 본인의 기여는 DB·API 설계와 웹·백엔드 중심의 개발이며, 모바일 화면의 개별 구현까지 본인 소유로 확대하지 않습니다.

## 대표 흐름 2 — 매장 기록에서 수익 분석까지

수익 항목과 기준 비율을 정의한 뒤 매장별 금액을 리포트에 기록하고, 저장된 값을 웹·모바일에서 분석 자료로 구성합니다. 이 과정에서 입력 항목, 리포트 회차, 유형별 합계, 기준 대비 결과, 총평과 개선 방향이 연결됩니다.

KPC가 제공한 계산 기준을 팀이 구현했다는 설명과, 실제 소스의 항목·저장·분석 흐름을 구분해 근거로 삼았습니다. 공식 명세의 모든 수식과 일치하는지, 어떤 시점의 규칙이 최종 운영에 반영되었는지까지 확인한 것은 아닙니다.

특히 보관된 모바일 주소와 서버 라우트의 불일치, 점주 유형의 저장 제한이 있습니다. 제품의 목표를 설명하되, 해당 보관본에서 모든 사용자 흐름이 바로 실행된다고 표현하지 않습니다. [백엔드 처리와 제한](backend-and-data.md)

## 이 프로젝트가 보여주는 개발 경험

핵심은 대규모 트래픽이나 성능 개선 수치가 아닙니다. 작은 팀에서 고객 업무를 이해하고, 이를 회원·소속·항목·리포트 데이터와 API로 설계한 뒤 웹과 모바일의 사용 흐름에 연결한 경험입니다.

JavaScript 중심 기술 선택, DB·API 설계, 백엔드와 웹 구현, 인증·업무별 권한 처리, 외부 기능과 배포 구성에 대한 이해를 함께 설명할 수 있습니다. 다만 공동 작업의 결과와 개인 구현 범위는 구분합니다.

## 포트폴리오에 포함하지 않은 주장

같은 지역 점포 비교 화면은 제목과 이동 버튼 수준이어서 완성 기능으로 분류하지 않았습니다. 다른 점포 비교에는 조회·표시 코드가 있지만, 이를 업종·지역 전체를 대상으로 한 검증된 벤치마킹이라고 소개하지 않습니다. 모바일 통계의 일부 선언, 사용 여부가 확인되지 않은 권한·설정 테이블도 완성 기능으로 확대하지 않았습니다.

기존 소개의 “교육”이라는 표현에 대응하는 독립적인 교육 업무 구현은 확인하지 못해 핵심 제품 범위에서 제외했습니다. 서버 호스팅 사업자, 사용자 수, 매출 성과, 성능 향상, 가용성, 공식 직책에 대해서도 근거 없는 내용을 넣지 않았습니다.

## 근거와 공개 범위

**소스 확인**은 해당 화면·라우트·데이터 구조·처리 코드가 존재한다는 뜻입니다. **본인 기여**는 당시 참여자가 확인한 담당 범위를 뜻합니다. 도식은 확인된 구조를 축약한 개념 모델이며, 미확인 연결과 보관본 차이는 별도로 표시했습니다.

원본 상용 소스, 운영 기록, 인증서·키, 실제 고객 데이터와 상세 계산 기준은 공개하지 않습니다. 고객 데이터의 출처가 확인되지 않은 화면과 원본 상세 ERD 대신, 식별정보 없는 시스템·도메인 개념도를 사용했습니다.
